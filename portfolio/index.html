Main project

SpicyChat QoL Extension

the thing that started all of this xD a configurable Chrome/Chromium + Firefox extension for chat helpers, filtering, saved lists, creator tools, backups, UI cleanup and a lot more.

  • current public release: v0.2.14
  • settings are meant to be optional instead of forcing one workflow
  • local-first where it makes sense, with public source and contribution docs

Android

SpicyChat QoL Android

a dedicated Android wrapper that runs the shared QoL features with mobile-friendly handling instead of trying to pretend a phone is just another desktop browser.

  • persistent login + navigation-safe QoL injection
  • local settings import/export
  • normal QoL updates can update without needing a new APK every time

Diagnostics

SpicyChat Inspector

a separate diagnostic extension i made because “the page feels slow” isn't very useful if i can't figure out why it feels slow.

  • network/API and page lifecycle captures
  • DOM activity, Long Tasks and animation-frame blocking
  • post-generation render timing + clean-vs-QoL comparison work

the diagnostic project is public, but raw captures can contain a lot of page/session detail so i don't just dump those onto the internet by default.

how i build / test things

“this feels broken” is the start, not the diagnosis.

i usually start with something that annoys me or somebody reports, reproduce it, figure out what is actually happening, build a fix/tool, test it, then let other people find the things i missed xD

1idea / reportsomething is annoying, missing or broken
2reproducereduce variables and confirm what actually happens
3buildprototype the smallest useful version
4measure + testbrowser/device checks, diagnostics where needed
5users break itfeedback catches setups i don't have
6fix + releaserepeat basically forever :D
performance

Long-history chat lag

when large chats started behaving badly, i used dedicated diagnostic captures instead of treating every slowdown as “QoL is slow.” Inspector records things like Long Tasks, animation-frame blocking, DOM activity and render timing, and i've run long/clean-profile captures to separate native behavior from extension work where possible.

cross-platform

Android wrapper

rather than making a completely separate Android feature set, the app reuses the shared QoL code and adds the mobile-specific pieces around it: WebView handling, persistent login, navigation-safe injection, settings import/export and updating.

data / UI

Exact public message counts

instead of making a separate request for every bot, QoL can use the exact public count already returned in SpicyChat's listing data and replace the rounded card value. that keeps the feature useful without turning it into a pile of extra per-card requests.

built with users, not just for users

making it public was kinda the point.

QoL started as something i was making for myself, but pretty quickly there wasn't much point in fixing/improving all this stuff if only i could use it xD

since then people have tested builds, reported bugs, suggested features and explained how they use SpicyChat on setups i don't have. some of those suggestions became actual features, and quite a few fixes started with somebody going “hey this is doing something weird.”
