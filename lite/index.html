Recipes

Save it once. Rebuild it later.

The recipe is the important part of the custom-build system. It stores module IDs, not a separate fork of the extension, so the same setup can later be rebuilt against a newer source version.

Why modules first?

Actually leave code out.

A Lite build should not just be the Full extension with switches turned off. The goal is to physically omit unused runtime groups and their settings/background pieces, while keeping required shared dependencies.

Updates later

Same recipe, newer QoL.

Core updates will remain required. Optional-module update controls are planned around the saved recipe so a custom build can be rebuilt without making you choose everything again.
